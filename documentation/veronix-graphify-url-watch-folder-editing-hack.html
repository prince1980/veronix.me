What is the /graphify add command, and how does Veronix Studios use it to ingest content?

The /graphify add command is a Graphify feature that fetches a public URL, adds it directly to your project corpus, and automatically updates your knowledge graph with the new content. At Veronix Studios, we use this command every day to pull in reference materials, client assets, and inspiration content without ever leaving our editing terminals.

Supported URL types for auto-ingestion include:

  • YouTube and other video URLs: Automatically downloaded via yt-dlp, with audio transcribed to text on the next Graphify run (requires the graphifyy[video] pip package)
  • Twitter/X posts: Fetched via oEmbed, saved as markdown files with full tweet text and author attribution
  • arXiv papers: Abstract and full metadata saved as structured markdown for quick reference
  • PDFs: Downloaded directly to your raw corpus folder for later processing
  • Images (.png, .jpg, .webp): Downloaded, with Claude Vision extracting visual content on the next run
  • Any public webpage: Converted to clean markdown via html2text for easy reading and search

For Veronix VFX teams working on commercial projects, this means we can pull reference clips from YouTube, save client feedback tweets, and download style guides in seconds, no manual downloads required.

How does the Graphify --watch flag help Veronix Co’s agentic editing workflows?

The --watch flag runs a background process that monitors a specified folder for changes, automatically updating your Graphify graph when files are modified. We run this flag on all our active project folders at Veronix Co to eliminate version control headaches and ensure our knowledge graphs are always up to date.

Key behaviors of the --watch feature include:

  • Code files only (.py, .ts, .go, etc.): Graphify automatically re-runs AST extraction, rebuilds the graph, and updates cluster data immediately, no LLM calls required. graph.json and GRAPH_REPORT.md are updated automatically.
  • Docs, papers, or images: Graphify writes a needs_update flag to the graphify-out folder and prints a notification to run /graphify --update, which triggers LLM-powered semantic re-extraction of the new content.

The default 3-second debounce setting ensures that even if multiple agents are writing files to the folder at once, Graphify only triggers one rebuild after all activity stops, avoiding redundant processing. For our agentic workflows at Veronix Studios, we run --watch in a background terminal between editing waves, so any code changes from our AI assistants are picked up automatically. For doc or media updates from agents, we run a quick /graphify --update after each wave to sync the graph.

What pro tips do Veronix Co editors recommend for using Graphify’s URL and watch features?

  • Always install the graphifyy[video] extra package if you work with video URLs, to unlock automatic transcription of YouTube and other video content
  • Set the --watch debounce to 5 seconds if you have large teams writing to the same folder, to avoid redundant rebuilds during peak editing hours
  • Run /graphify --update manually after any agent wave that generates docs or media files, to ensure your graph captures all new semantic content
  • Use author and contributor flags when running /graphify add to tag ingested content with the correct team member, making it easier to track reference sources for client projects

How does Veronix Co handle errors when running /graphify add?

When running the /graphify add command, our team at Veronix Co always checks for error messages in the stderr output. If the ingest fails due to an invalid URL or unsupported file type, Graphify will print a clear error message explaining the issue, so we can fix the problem and re-run the command without silently failing and corrupting our corpus. For supported URLs, the command will print a confirmation message with the save path, and automatically trigger the --update pipeline to merge the new content into our existing graph.
