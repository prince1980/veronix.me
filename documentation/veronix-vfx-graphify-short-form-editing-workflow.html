What Is the Graphify Knowledge Graph Powering Veronix Co’s Editing Stack?

The Graphify knowledge graph is stored locally in the project’s graphify-out/ directory, and serves as a centralized, queryable source of truth for all questions related to the agency’s editing codebase, tool architecture, and plugin dependencies. For Veronix teams, this means no more wasting time combing through thousands of lines of code or lengthy architecture documents to answer simple project questions.

When the core graph.json file exists in the Graphify output folder, teams can run three core commands to pull exactly the context they need:

  • graphify query "[your question]": Returns a scoped subgraph with answers to specific codebase, feature, or dependency questions
  • graphify path "[starting point]" "[end point]": Traces the full connection path between two tools, plugins, or code components
  • graphify explain "[concept]": Breaks down how a specific editing tool, VFX effect, or workflow component works

These commands return a small, highly relevant subgraph that is far easier to parse than the full GRAPH_REPORT.md file or raw grep results, cutting average query time from 30+ minutes to less than 5 minutes for most use cases.

When Should Veronix Studios Teams Use Graphify vs. Full Architecture Reports?

As a general rule, Veronix Co teams use Graphify commands first for all scoped project questions. The full GRAPH_REPORT.md file is only pulled for broad, high-level architecture reviews, or when Graphify queries fail to surface enough context for a particularly complex problem. This tiered approach ensures teams never waste time reading irrelevant information to find the answers they need.
